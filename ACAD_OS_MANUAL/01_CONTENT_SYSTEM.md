# 01 · The Content System

Everything the learner practises flows from one object — the **question record** — organized by a **taxonomy**, cleaned by a **QA loop**, and tagged for **adaptivity**. This file is the whole content engine. (The defect classes the QA loop hunts are catalogued in `04`; the scripts are in `05` / `scripts/`.)

---

## 1. The question record (the atom)

Every question, math or otherwise, is one JSON record. The fields that matter:

```
id              unique, structured: KM-L{level}-{PILLAR}-{serial}   (e.g. KM-L5-NT-0042)
                legacy_id keeps the source's original id for traceability
stem            the question text (may embed math as $LaTeX$)
choices         options for MCQ; empty for typed-answer questions
correct_answer  the correct CHOICE INDEX (0-based) for MCQ
correct_value   the correct typed value for integer/numeric questions
answer_min/max  optional accept-RANGE for fraction/decimal answers (grading tolerance)
hint            a nudge — must NOT contain the answer
solution        full worked explanation (+ solution_steps), revealed after answering
difficulty / irt_b   orders easy → hard within a topic (the ladder)
tags            subject / chapter / topic labels
visual_svg      inline SVG figure (vector, renders crisp)  ┐ a question has at most
visual_png      base64 image figure (for scanned figures)  ┘ one; many have none
source          provenance (which paper / sheet / author) — drives trust + the verified pool
verified        backend-only flag; true when a trusted source is present
video_url       optional per-question video solution (served in practice, NOT in contest)
skill_id        which concept cluster this belongs to        ┐
skill_seq       this concept's rung on the topic ladder       │ the adaptive tags
skill_difficulty parent concept's difficulty (inherited)       │ (added by the clusterer,
skill_rank      difficulty order within the concept            ┘  §6)
```

**The golden invariant:** when you fix one thing, you change one field. `correct_answer`, `correct_value`, `choices`, `hint`, `difficulty`, and the skill tags are **locked** unless the fix is specifically about them. Every pass backs up the file first and asserts only the intended field changed. (This is operating principle #7 — it is the single most important habit in the content system.)

**Grading** lives in exactly one place per surface and only ever compares the learner's input to the *stored* key — it never computes the key. Two modes: pick-the-option (compare indices) and typed (exact match, or `answer_min ≤ x ≤ answer_max` for decimals). The shared helper is `numeric_correct()` in `content_store_level.py`.

## 2. The taxonomy (the shelves)

A **4-level hierarchy**. The names are math-flavored but the *shape* is universal — map it onto any exam (see `HANDOVER_MINIAPP/`).

```
LEVEL            →   PILLAR / STRAND        →   TOPIC            →   CONCEPT (skill_id)
L1…L8                9 olympiad strands         "GCD & LCM" …        one idea, many variants
```

**Levels (the olympiad ladder).** L1=Grade1-2, L2=G3-4, L3=G5-6, L4=G7-8, L5=IOQM, L6=RMO, L7=INMO, L8=IMO (intentionally empty / coming-soon, hidden by an empty-topic filter). Counts roughly: L1≈8.7k, L2≈5.3k, L3≈2.8k, then the thinner upper tiers L4–L7.

**The 9 olympiad strands** (in `OLYMPIAD_STRANDS`, `content_store_level.py`): Algebra (ALG), Number Theory (NT), Combinatorics (COM), Geometry (GEO), Combinatorial Geometry (CGEO), Trigonometry (TRIG), Basic Mathematics (BMATH), Arithmetic (ARITH), Algebra-Number Theory (ALGNT). A pillar is **never shown to the user as a code** — it carries a friendly display name.

**Two separate stores, by purpose:**
- `content-live/olympiad/L{1-8}/L{n}_{PILLAR}_{topic}.json` — the olympiad ladder.
- `content-live/curriculum/{board}/grade{n}/` — school curriculum (NCERT, IGCSE/Cambridge, ICSE, Singapore, US Common Core), grade-tagged.

This olympiad-vs-curriculum split, and the level re-tag from grades to L1–L8, were a deliberate reorganization (the story is in `06`). The key learning: **separate the competition ladder from the school syllabus** — they have different progressions and different users.

## 3. Where content came from (provenance)

Content was never generated by the AI. It came from real sources and was *transformed*:

1. **Kangaroo-derived bank** (the L1–L3 base) — competition questions, story-rewritten into consistent narratives, then later *stripped* of decorative filler (see the filler-prefix saga in `04`).
2. **Vedantu academic library** — ~140 assignment PDFs (IOQM/RMO/INMO + grade courses) and 6 Google Sheets, the competition curriculum from Grade 3 → ISI/CMI/Putnam. Ingested via the pipeline in §4.
3. **Authored books** — two from-scratch teaching books (L2, L3) written like a maths expert would, with every answer brute-force-verified in Python. (These are *books*, in the Library — `02` — not bank questions.)

**The provenance rule:** every served question traces to a source, stored in `source`. That field also powers the **verified pool**: when a level has enough verified questions, its daily quiz auto-upgrades to serve only trusted content. No UI badge — it's a backend preference.

## 4. The ingestion pipeline (source → question records)

Used to turn source PDFs into questions. Script: `scripts/ingestion/ingest_quiz.py`.

**The hard-won lesson that shapes the whole pipeline:** *extracting a PDF's text mangles math.* Superscripts flatten (`2023^2023` → `20232023`), an OCR'd `+` becomes `.` (turning a sum into a product and flipping the answer), fraction options like `1046½` extract as `1·1046·2`. **You cannot trust extracted text for the math.** Two safe paths emerged:

- **Faithful image path (default for anything with notation/figures):** render the problem region of the page to an image (`visual_png`, a tight crop between consecutive question markers). The student sees the *real* page — exponents, √, figures intact. No reconstruction, nothing to mangle.
- **Typed path (only for clean, computable items):** reconstruct the question as text/LaTeX, then **brute-force the answer in Python and require it to equal the source key** — else HOLD the item. This is the only way typed ingestion is safe.

**Grading by answer type, the safe way:**
- **MCQ → keep as real letter-choice MCQ, graded by the key's letter index.** *Never* convert option text to a number (the `1046½` trap). The image shows the real options; the student taps the letter.
- **Integer →** typed, exact match.
- **Fraction/decimal →** typed with an accept-range (`answer_min`/`answer_max`, e.g. ±1%).

**Important reversal:** the image-based "solve the problem shown" questions were tested on-device and pulled from the *served bank* — they looked unfinished outside a book. They now live **only in the Library books**; a backlog (`CONVERSION_BACKLOG.json`) tracks converting them to clean typed HTML/LaTeX, slowly, only when 100% certain. The lesson: **a faithful image is great inside a book, weak as a standalone practice question.**

## 5. Answer-key validation (the most important QA)

The most dangerous defect is a **wrong answer key** — the child does the math right and is told they're wrong. Early QA treated `correct_answer` as locked and never math-checked it; that is exactly how wrong keys slipped through.

**The principle: every *computable* family gets its own validator** that recomputes the answer and flags `recompute ≠ key`. Built so far:
- single-step integer add/sub/mul/div word problems + explicit "what is A op B" (caught 11 wrong keys, all keyed to a distractor — e.g. 3 cats × 4 legs keyed "7" = 3+4);
- percentage "sold vs left" (caught 1);
- N-part ratio "larger/smaller angle" (caught 1: ratio 7:2 "larger" keyed to the smaller term);
- geometry formula families (rect/triangle area, angle-sum) — found 0 mis-keyed but confirmed clean.

**Still un-validated** (open work, could hold wrong keys): fraction/decimal arithmetic, multi-step word problems, combinatorics counts, probability. Each needs its own validator before that family can be fully trusted.

**False-positive guards baked into the validators** (hard-won — see `04` for the full list): "tri**angle**" contains "angle"; `correct_answer` is a choice *index* not a value; composite/multi-step figures break single-formula validators (exclude them).

## 6. The QA loop (the A–N scanner)

This is how a whole level is checked for *every* known defect without eyeballing thousands of questions. Script: `scripts/content_qa/content_qa_scan.py` (read-only; reports, never edits).

**The method (the repeatable per-level loop):**
```
run content_qa_scan.py  →  it reports counts for detectors A–N
   →  fix every flagged item (one field, backed up)  →  re-run  →  repeat until TOTAL = 0
   →  when a NEW defect appears, add a detector for it FIRST, then fix
```
You do **not** eyeball 8,766 questions. You run the harness, fix what it flags, re-run. When a live bug surfaces a new defect class, the first move is to *write a detector for it* so it can never hide again.

The scanner runs **14 detectors, A–N**, one per defect class (placeholders, ratio-key, semicircle-as-circle, absent-figure, Venn/tree spoilers, empty-stem, hint-leak, value-based duplicates, fake-svg, pattern-missing, decorative-figure-on-logic, directional-unanswerable…). The full catalogue with detector signals, examples, and fixes is `04`. As of the last pass, **L1 = 0 and L2 = 0** across all detectors; L3–L7 + curriculum still carry flags pending their own loops (the open work).

**The verification harness that gates every change:**
- `scripts/verification/pre_deploy_check.py` — counts + required-field + SVG-ref check; must end "ALL CHECKS PASSED".
- `scripts/verification/smoke_level_v3.py` — 17 assertions (no answer-leak at fetch, economy consistency, idempotency); must stay 17/17.

## 7. Adaptive tagging (concept clustering)

Raw questions are full of near-duplicates (the same idea with different numbers). To drive adaptivity, they're grouped into **concepts**. Script: `scripts/content_qa/cluster_concepts.py` (idempotent — re-run after any import).

**How it works:** each stem → a signature (numbers → `#`, character names + "Help X figure out:" stripped, operators normalized so arithmetic facts don't wrongly merge, math structure kept) → **leader clustering** at Jaccard ≥ 0.70. (Not single-linkage union-find — that chained unrelated sequences into one giant blob; the threshold + leader method was the fix.) Result: ~8.2k concepts across ~30k questions.

It writes **additive** tags only (0 existing-field changes, verified by a per-question core-hash):
- `skill_id` — the concept this question belongs to.
- `skill_rank` — difficulty order *within* the concept (the variant ladder).
- `skill_seq` — the concept's rung on the *topic* ladder (ordered by difficulty).
- `skill_difficulty` — the concept's difficulty, inherited by all its variants.
- `is_skill_original` — marks the one canonical exemplar per concept.

**Why it matters:** this is the data the adaptive engine reads. A concept with many variants (L1/L2 have big families — 100+ rectangle-area variants) supports a *ladder within the concept* (drill easier variants on a miss); a concept with one variant (L3/L7 are mostly bespoke) means *broaden across* concepts instead. The size distribution tells you where adaptivity pays off.

## 8. How to do a content task (the checklist)

For a new cowork, any content job follows the same shape:

1. **Source it.** Get the material from an authoritative source you have rights to. Never generate it.
2. **Transform, don't author.** Faithful-image for anything with notation/figures; typed only for clean computable items (and brute-force-validate the key).
3. **Tag** subject/topic; set `difficulty` from the source's signal, not your judgment.
4. **Cluster** (`cluster_concepts.py`) to assign skill_ids.
5. **Scan** (`content_qa_scan.py`); fix flagged items one field at a time, backed up.
6. **Verify** (`pre_deploy_check.py` + smoke tests green).
7. **Deploy** (`./deploy.sh` — content is baked into the backend image; no app rebuild).
8. **Log** the pass in `CLAUDE.md` with counts.

Slow and certain. A wrong key is worse than a missing chapter. Read `04` before you touch anything.
