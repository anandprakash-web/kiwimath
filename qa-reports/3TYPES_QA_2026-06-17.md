## The 3 error types

### Type A — unsubstituted template placeholder (20 questions)
A generator left `{token}` literals unfilled. Detector strips `$…$` math first (so valid LaTeX like `\dfrac{abc}{4K}`, `Σ_{k}`, `x^{2k}` is **not** flagged) and treats any brace inside an SVG as real.

| Placeholder | Where | Fix | IDs |
|---|---|---|---|
| `{b}k` | SVG angle label (2nd angle) | → 2nd ratio term | L4-GEO-0012/0013/0014/0015 |
| `{j}` | hint | → # of ones in stem | L5-COM-0181/0182/0183/0184 |
| `{n}` | hint | → # of chords in stem | L5-GEO-0229/0230 |
| `{rem}` | solution + steps | → computed remainder | L7-ALG-0021/0022/0023/0024 |
| `Erd\H{o}s` | stem/solution | → `Erdős` (LaTeX accent renders ugly in prose) | L6-COM-0072/0114, L6-NT-0040/0041/0042, L6-GEO-0250 |

### Type B — wrong answer key (1 question)
**KM-L4-GEO-0015** — "ratio 7:2, find the larger angle" was keyed **40** (= 2·20, the *smaller*) instead of **140** (= 7·20). The generator always took the *second* ratio term as "larger" — fine for 4:5 but wrong whenever the first term is bigger. Fixed `correct_value`/`correct_answer` + solution.
Validators also re-checked the 3-part triangle ratios (1:2:3 …) and the L5 similar-triangle family — **all correctly keyed** (they only looked wrong to a naive scanner because "tri**angle**" contains "angle").

### Type C — image doesn't match the stem (2 questions)
**KM-L4-GEO-0151 (r=7)** and **KM-L4-GEO-0152 (r=14)** — "semicircle" questions were drawn as **full circles**. Redrawn as proper semicircles (flat diameter at bottom, arc on top, radius labelled), render-verified.

### Type D — confusing question wording (3 questions)
**KM-L4-ALG-0198/0199/0200** — "In the pattern 1, 3, 5, 7, … which figure number has exactly 21 dots?" invoked a *figure/dots* picture model with **no figure shown**, forcing the student to imagine an absent diagram. Principled detector (stem promises a visual — "shown"/"the figure"/"figure number"/"dots"/"shaded" — but no `visual_svg`/`visual_png`) returned **exactly these 3** across all of L4–L7.

Reworded to plain sequence-position language, answer unchanged:
> *"In the sequence of odd numbers 1, 3, 5, 7, …, what is the position of 21? (1 is the 1st, 3 is the 2nd, 5 is the 3rd, …)"* → 11

The forward siblings 0188–0194 ("how many dots in figure 5?") **do** have a real labelled dot-figure (Fig 1–4 = 1/3/5/7 dots, render-verified) and were left as-is — they're standard, clear visual-pattern questions. The L5 "L-shaped **figure**" area questions use "figure" in the ordinary geometric sense — not this error.

Only `stem` changed on the 3; hint/answer/solution/IRT untouched. Answers preserved: 11 / 16 / 21. (Extended later to 2 more in L2-GEO — see below.)

### Type E — figure reveals the solution (29 questions)
The figure has already done the work, so the child just reads/counts the answer:
- **Venn (16):** `KM-L4-COM-0147-0162` — circles showed the *derived* region split (e.g. 11 | 9 | 7 = 27, where 11 = 20−9 and 7 = 16−9 are not in the stem).
- **Tree (13):** `KM-L4-COM-0001/0003/0129/0133-0145` — the tree drew every outcome, so leaf-count = answer (12 dots for 3×4).

**Detector:** ≥2 overlapping circles whose region numbers sum to the answer (with derived values) → Venn; ≥6 lines + leaf-circles ≈ answer on a "how many ways" stem → tree. **Guard:** "answer appears as a label" alone is *not* enough — for MCQ, `correct_answer` is a choice index (0–3) that collides with small numbers in legitimate *givens* figures.

**Fix:** removed the 29 spoiler figures (all text-answerable) and dropped "Using a tree diagram," from 5 stems. Locked fields untouched. Only family found was L4 combinatorics.
